# Interface language support

The workbench shell supports nine UI languages:

| Code | Language |
|---|---|
| `zh-Hans` | 简体中文 |
| `zh-Hant` | 繁體中文 |
| `en` | English |
| `ja` | 日本語 |
| `ko` | 한국어 |
| `fr` | Français |
| `it` | Italiano |
| `pt` | Português |
| `es` | Español |

Select the language from the fixed sidebar (and the landing header / Settings).
The choice is stored in `localStorage["br.lang"]` and applied client-side by
`i18n.js`; `i18n-data.js` contains the keyed source strings and translations.

## Coverage and precision

Navigation, primary actions, page headings, settings labels/options, long-form
guide/methods copy and agent/result labels are localized. `i18n-auto.js` carries
799 auto-extracted rendered source segments (Google-translated offline at build
time); curated strings and technical wording are preserved over auto values. Evidence values, CWE identifiers, model output and
long technical source text are **not** machine-translated: keeping the original
wording avoids silently changing a security claim. The Settings language row
states this boundary explicitly.

## Adding a language

1. Add the code and native name to `names` in `i18n-data.js`.
2. Add the translation table under `langs` using the same keys as `keys`.
3. Ensure `_lang_switch.html` contains a matching `data-lang-set` button.
4. Reload; missing keys fall back to English rather than blank text.

## Implementation notes

- `i18n.js` walks text nodes, preserves leading/trailing whitespace, and stores
  originals in a `WeakMap` so switching back to Chinese restores exact text.
- Attributes (`placeholder`, `title`, `aria-label`, `alt`) are translated from
  stored originals.
- A `MutationObserver` handles dynamically inserted UI; code/pre blocks and
  explicit `data-i18n-ignore` regions are skipped.
- `document.title` is translated/restored with the same original snapshot.

# BinaryRepair: quality/efficiency re-evaluation (2026-11-12)

Scope is deliberately narrow and reproducible: static rule repair on five
synthetic snippets plus the read-only evidence evaluator over the local mock
fixture. **No binary was executed in this probe**, so this document does not
claim a real-world binary repair success rate. The machine-readable output is
[`repair-evaluation-2026-11-12.json`](repair-evaluation-2026-11-12.json),
generated by `scripts/benchmark_repair.py`.

## 1. Code-repair rule probe

| Sample | Expected | Detected | Patch emitted | p50 | p95 |
|---|---|---|---|---|---|
| `shell=True` | CWE-78 | CWE-78 | yes | 0.044 ms | 0.093 ms |
| `eval(user_input)` | CWE-95 | CWE-95 | no | 0.024 ms | 0.028 ms |
| `strcpy(dst, src)` | CWE-121 | CWE-121 | yes | 0.032 ms | 0.042 ms |
| SQL string interpolation | CWE-89 | not matched | no | 0.011 ms | 0.013 ms |
| path `os.path.join` | CWE-22 | not matched | no | 0.007 ms | 0.007 ms |

- Detection: **3/5 (60%)**; patch emitted: **2/5 (40%)** on this deliberately
  small, known-sample set.
- Rule mode is deterministic and sub-millisecond; it is not a model-quality
  claim and these five cases are not a recall benchmark.
- Honest gap: CWE-89/CWE-22 patterns and an `eval` remediation template are not
  implemented. The UI must say “未匹配到已知漏洞模式”, not imply safety.

## 2. Evidence evaluator probe

- 80 iterations over a mock snapshot: **p50 0.017 ms / p95 0.051 ms**.
- The empty mock snapshot yields an observability index of **5.8/100** and
  explicit bottlenecks: `no_obligations`, `no_artifacts`, `no_comparison`,
  `no_verdict`. This is the intended behaviour: missing evidence lowers
  coverage and is never promoted to a pass.
- `not_verdict: true` is part of every response.

## 3. Existing binary artifacts

Three candidate packages are present. All `SHA256SUMS` verify; the primary
`p1-routea-package-2026-11-07` package has a 25 KB original and candidate, a
passing metadata audit (`changed_inside_intervals`, `entry_unchanged`,
`no_wx_segment`, `relocations_recorded`, `same_file_size`), one valid test
case, and V1/V2/V5 evidence directories. `readelf_available` is **false** on
this macOS host, so the audit cannot claim readelf-level confirmation.

Only one `status.json` is currently present; its verbatim phase is
`generating`. The packages are therefore partial hand-off artifacts, not a
completed acceptance run. We do not compute a success rate from them. The
result screen now exposes attempts, V0–V5 coverage, obligation denominators,
artifacts and raw JSON so a reviewer can see this directly.

## 4. What was upgraded from the research baseline

The global direction is away from “LLM says the patch is good” toward
scope-bound, independently checkable evidence:

- **NIST SP 800-218 SSDF** — secure development and verification practices:
  <https://csrc.nist.gov/pubs/sp/800/218/final>
- **CWE / CWE Top 25** — defect taxonomy and remediation language:
  <https://cwe.mitre.org/top25/>
- **SLSA v1.0 / in-toto** — build provenance and supply-chain attestations:
  <https://slsa.dev/spec/v1.0/>, <https://in-toto.io/>
- **OpenSSF Scorecard / OSS-Fuzz / AFL++** — continuous project security and
  fuzz regression.
- **CVEfixes / Vul4J / Defects4J** — repair benchmarks for reproducibility.
- **Alive2 / CBMC / KLEE / angr** — translation validation, bounded model
  checking, symbolic execution.
- **Diaphora / BinDiff** — binary diffing; differences are observations, not
  correctness proofs.

Implemented in this iteration:

1. Read-only `/api/jobs/{id}/evaluation` with coverage, denominators, gaps and
   observability index; **no verdict derivation**.
2. Result/evidence control room: V0–V5 matrix, obligation filters, attempts,
   artifact fingerprints, raw JSON, copy/export.
3. Light/dark ambient material and full-shell language switching (including
   auto-extracted long-form page copy) so the evidence UI is usable across
   languages and themes.
4. Explicit N/A for zero/missing denominators, `not_run` never rendered as a
   pass, and missing comparison/artifacts surfaced as bottlenecks.

Still not implemented (and therefore not claimed):

- Alive2/CBMC patch-equivalence integration; full SBOM/provenance generation.
- ARVO/CVEfixes/Vul4J large-scale recall/precision evaluation.
- Automated Docker/QEMU execution of real samples in this environment.
- Any production approval or formal whole-program equivalence.

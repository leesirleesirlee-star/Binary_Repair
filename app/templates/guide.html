MANUAL / BINARYREPAIR

使用说明

从第一次启动到证据导出：一份可照着操作、也能理解“为什么”的完整手册。 每一步都给出操作、预期结果和失败时该看哪里；技术结论与演示数据严格分开。

0 · 系统总览

BinaryRepair 不是“一个模型给出一句结论”，而是一条可追溯的证据链： 输入 → 规划/规则 → 候选补丁 → 证据 → 验收结论。 对话只负责引导和解释；结论由验收引擎给出，页面不自行判定。

先选路径：只想看代码问题 → 第 2 节；要修二进制 → 第 3 节； 只是看看界面 → 工作台的“演示会话”；需要长期留存 → 第 4 节历史与导出。

1 · 启动与登录

  1. 解压并启动：macOS/Linux 运行 ./start-gui.sh；Windows 双击 start-gui.bat。首次会创建 .venv 并安装依赖。
  2. 复制带 token 的地址：终端会打印 http://127.0.0.1:8123/?token=...；直接点开或粘贴到浏览器。
  3. 确认已登录：页面左上角出现工作台侧栏，顶部没有 401；地址栏的 token 会被自动移除并换成会话 cookie。
  4. 选择模式：工作台启动卡里选“真实任务”或“演示会话”，再点主按钮。两者区别见卡片下方说明。
现象原因处理
401 Authentication required没有带 token 或 cookie 失效重新打开终端打印的完整地址；不要只访问 /
端口被占用8123 已被其他进程使用BINARYREPAIR_PORT=8124 ./start-gui.sh
样式缺失/旧页面浏览器缓存Cmd/Ctrl + Shift + R 强制刷新

1.1 · 配置模型 API Key

工作台顶部「配置模型」按钮控制右侧 Key 面板：桌面端展开/收起面板，手机端打开/关闭浮层。 按钮文案会随状态在「配置模型 / 收起模型」之间切换。

  1. 打开配置：点顶部「配置模型」；首次使用显示「未配置」。
  2. 填写用户名：用户名必填，用于本机显示和模型请求上下文（operator_username）。
  3. 填写 Key：Key 只用于 provider 认证；保存后显示「已填充」和用户名，不回显完整 Key。
  4. 保存并测试：保存后自动测试连接；失败会明确显示原因，不静默伪装成功。
  5. 清除：点「清除已保存 Key」需二次确认；清除后回到未配置，可重新填写。
存储与边界：Key 和用户名一起保存在本机服务端（Windows DPAPI，其他平台 0600 文件）； 不写入日志、不进入导出。环境变量配置的 Key 在页面只读，不能从页面清除。

2 · 代码修复：从粘贴到补丁

适用于 Python、C、JavaScript 等常见片段；不执行代码，只做静态规则/模型分析。

  1. 进入新建会话：工作台主按钮 → 真实任务；或直接在输入框粘贴代码。
  2. 提供代码：可用 ``` 围栏，也可直接粘贴多行代码；支持从 + 菜单上传文本文件、拖放或粘贴文件。
  3. 发送：默认 Enter；若在设置改为 Ctrl/Cmd+Enter，则按对应组合键。
  4. 读结果卡：先看标题/风险级别/CWE，再看“覆盖范围”和“警醒”；展开每条 finding 看证据、影响、修复、参考。
  5. 取补丁：复制补丁、复制差异；长代码点“展开全部”。
  6. 复核：把补丁贴回你的项目测试；静态建议不是验收结论。
规则模式

未配置模型 key 时使用本地规则，结果确定、可离线复现；覆盖常见 sink，不覆盖业务语义。

模型模式

服务端配置 key 后，模型给出补丁建议；用户名会作为 operator_username 上下文随请求发送，Key 只用于认证。失败自动回退规则并标注，不会静默冒充模型结果。

不要误读：“发现 2 处问题”是静态命中；“已生成补丁”是可复核建议，不等于“漏洞已修复”。

3 · 二进制修复：引导式建单

  1. 描述缺陷：在对话里写清样本、函数/输入、期望行为；后端返回引导计划。
  2. 上传样本：点 + → 上传二进制样本，或把文件拖入上传区；不是所有格式都支持。
  3. 填用例与契约：有效输入、无效输入、环境、禁止行为、可接受结果；这些字段会成为验收义务。
  4. 逐步复核：每一步可返回修改；助手只解释，不替你点“创建任务”。
  5. 创建任务：确认摘要后点击创建；任务页每 2 秒刷新状态。
  6. 看证据：时间线、修改前后、诊断/义务、产物；未回传显示等待占位，不显示 not_run 当作已执行。
  7. 导出：JSON/HTML 报告用于复核；导出不代表生产批准。
证据优先：先看“证据来自哪一层”（静态/符号/动态/差分），再看结论； 不同层不能互相冒充。

4 · 任务、工作区与服务端历史

4.1 任务列表

侧栏只列本浏览器打开/创建过的任务，状态逐条向 controller 核对；不是“全量任务列表”。

  • 搜索：按名称或任务号过滤。
  • 置顶 / 重命名 / 删除：悬停任务行出现操作；删除只移除本机记录，后端任务仍在。
  • 后端已不可查：重启 mock 服务或内存任务清空后会显示；记录仍可追溯。

4.2 工作区

侧栏工作区菜单切换服务端配置的工作区；新建会话会带上当前选择。默认值可在设置中改为“跟随服务端默认”。

4.3 服务端历史

任务与草稿对话写入本机服务端 SQLite；同一服务实例内换浏览器可恢复。徽章显示 服务端历史 / 同步中 / 本地暂存 / 草稿已同步。

  • “新建任务”带 ?new=1：清空草稿后开始空白会话。
  • 旧标签页的过期写入会被 generation 守卫拒绝，不会复活已清空草稿。
  • 默认只监听回环地址；跨设备访问需要显式改变部署方式并保护 token。
清空要分清：“清空本机任务列表”只影响当前浏览器； “清空服务端历史”会删除所有任务/草稿对话，无法恢复。

6 · 输入工具栏与命令面板

6.1 加号菜单

  • 上传代码/文本文件：多选、单文件 400 KB；自动包成带文件名的代码块。
  • 上传二进制样本：只在引导建单的上传步骤可用；不是“把二进制塞进聊天框”。
  • 插入代码块 / 漏洞示例 / 审查模板：用于快速构造可复现输入。
  • 清空当前对话：删除本任务/草稿的本机与服务端记录后重开。
  • 拖放 / 粘贴文件：文本文件可直接入框；二进制会提示走样本上传。

6.2 命令面板

Ctrl/Cmd + K 打开：新建、工作台、连接器、方法、设置、指南、主题、侧栏。 支持中英文关键词；↑↓ 选择，Enter 打开，Esc 关闭。

7 · 连接器与插件

连接器是运行时接入点；插件是只读声明式清单。两者在页面分区展示，不混在一起。

  1. 在连接器页找目标工具（Ghidra、Rizin、angr、Frida、QEMU、GDB、Docker 等）。
  2. 按卡片中的环境变量/安装步骤准备；点环境变量名可复制。
  3. 重启 GUI，刷新页面；状态变为“已就绪”。
  4. 注意：“已就绪”只代表本机具备条件，不代表远端已连通或已实际调用。
  5. 插件清单放在 plugins/，页面只读取、不加载执行；需要时按清单协议自行接入。
官方入口： Ghidra · angr · Frida · QEMU · Diaphora · AFL++ · CWE

8 · 证据等级与验证边界

二进制修复建议采用分层证据，而不是“模型说可以”。阅读结果时按以下顺序提问：

层级回答的问题不能证明什么
V0 / 静态缺陷是否真实存在？调用点/边界是否正确？不能证明运行时可达
V1–V2 / 符号哪些输入能到达危险点？约束是否可满足？不能替代真实执行
V3 / 动态真实运行时是否触发、修复后是否消失？不能覆盖所有输入
V4 / 模型级目标函数内的安全性是否成立？不是全程序二进制证明
V5 / 差分只改了目标行为吗？其他行为是否异常？不等于形式化等价
不要把“工具跑通”当“补丁正确”：没有复现、没有差分、没有证据，最多是“看起来对”。 本工具的导出也不代表生产批准。

11 · 安全与隐私

  • 默认只监听 127.0.0.1；对外分享必须显式开隧道/改绑定，并保护 token。
  • 模型 Key 只保存在本机服务端，不回显、不写入导出；不要提交 .env。
  • 用户名会随模型请求作为 operator_username 上下文发送给 provider；它不等同于认证凭据。
  • 上传/修复后的二进制不在本机执行；解析、编译、符号分析属于受控 guest。
  • 插件是只读清单，不会自动加载执行；连接器状态不等于远端连通。
  • 演示数据是合成 fixture，可用于展示，不可作为真实修复证据。
